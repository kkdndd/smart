# 대교홀딩스 SMART 사업계획 관리 시스템

## 구성
- 프론트엔드: 정적 HTML/CSS(Tailwind CDN)/JS, 프레임워크 없음
- 백엔드/DB/인증/파일저장: Supabase (project ref: cbvjjocihktcbvfqsbyq, region: ap-northeast-2)
- 배포: Cloudflare Pages (정적 호스팅)

## 화면 구조 (중요)

상시 메뉴는 **네 개**뿐입니다. 일 년에 몇 번만 쓰는 기준정보 화면은 사이드바 맨 아래 **설정**으로 내려,
일상 업무와 섞이지 않게 합니다.

| 순서 | 메뉴 | 파일 | 누가 보나 | 안에 들어가는 것 |
| --- | --- | --- | --- | --- |
| 1 | 대시보드 | `dashboard.html` | 전체 | 전사·계열사·사업부 비교, 드릴다운, 내보내기 |
| 2 | 나의 할 일 | `home.html` | 전체 | 지금 내가 처리할 일, 마감 알림, 확정률 한 줄 |
| 3 | 사업계획 | `goals.html` | 전체 (경영진은 조회 전용) | 목표 목록·작성·상세·검토·변경요청 (상태 탭) |
| 4 | 실적 입력 | `progress.html` | 사업부·계열사 담당자 | 이번 기간 입력 / 한 해 전체 보기 |
| — | 설정 | `settings.html` | 관리 권한자 | 사업부·KPI 기준정보·계열사·계정·업무 흐름 안내 |

설계 원칙 세 가지입니다.

1. **로그인하면 대시보드가 열립니다.** 이 시스템의 목적은 현황을 보고 관리하는 것이고 입력은 그다음이므로,
   대시보드를 1순위에 둡니다. 대신 대시보드 맨 위에 **나의 할 일 띠**(`renderMyTaskStrip`)를 올려
   처리할 일이 묻히지 않게 합니다 — 가장 급한 한 건을 보여주고, 누르면 `나의 할 일` 화면으로 갑니다.
2. **메뉴는 기능이 아니라 일 단위입니다.** 검토·변경요청은 같은 목표를 다루므로 사업계획 안의 탭이 되었습니다.
   `review.html`과 `change-requests.html`은 그대로 쓰되 사이드바에서는 '사업계획'이 선택된 상태로 보입니다.
3. **빈 화면은 안내 자리입니다.** 목록이 비면 "없습니다" 한 줄 대신 다음에 할 일을 버튼으로 줍니다
   (`emptyStateHtml`). 처음 세 번만 보이는 안내 배너는 `introBannerHtml`을 씁니다.

### 내 차례 판정 (`myTurnKind`)
공이 누구에게 있는지는 `common.js`의 `myTurnKind(profile, goal)` 한 곳에서만 판단합니다.
홈의 할 일 카드, 사이드바의 빨간 배지, 목록의 '내 차례' 표시가 모두 이 함수를 씁니다.

| 역할 | 내 차례가 되는 상태 | 결과값 |
| --- | --- | --- |
| 사업부 담당자 | 작성 중 / 수정 요청됨 (담당 사업부 건만) | `write` / `fix` |
| 계열사 담당자 | 계열사 검토 중 → `review`, 작성 중·수정 요청됨 → `write`/`fix` | `review` 등 |
| 지주사 담당자 | 지주사 검토 중 | `approve` |
| 경영진 | 없음 (조회 전용) | `null` |

계열사 담당자에게 작성 단계까지 내 차례로 잡히는 것은, 사업부 담당자가 배정되지 않은 사업부에서는
계열사 담당자가 작성을 겸하기 때문입니다. 결재 단계 자체는 3단계 그대로입니다.

### 전역 필터와 드릴다운 (태블로 방식)
화면 위에 **회사 · 사업부 필터바**를 고정해 두고, 고른 값을 화면 사이에서 공유합니다
(`common.js`의 `getFilter` / `setFilter`, sessionStorage에 보관).
목록에서 '미머디'를 고른 뒤 현황으로 넘어가도 계속 미머디를 보고 있습니다.

현황의 **숫자와 차트는 모두 눌러서 들어갈 수 있습니다.**

| 누른 곳 | 가는 곳 |
| --- | --- |
| 전체 목표 / 확정 / 검토대기 숫자 | 사업계획 목록의 해당 탭 (`goalsLink`) |
| 상태 도넛 조각 | 그 상태의 목록 |
| 계열사별 달성률 막대 | 그 계열사의 목록 |
| 계열사 카드의 상태 배지 | 그 회사 + 그 상태의 목록 |
| **실적 미입력 목표** | **실적 입력 화면** (`progress.html?goal=…`) — 현황이 아니라 바로 입력하는 곳 |
| 목표값 미설정 | 목표 수정 화면 (권한이 없으면 상세) |

드릴다운 주소에는 `?company=` / `?bu=` 가 함께 실려 가고, 받는 화면은 `applyFilterFromUrl()`로 반영합니다.
지주사는 필터에서 **전체 회사**를 고를 수 있습니다. 이때 회사 이름은 **열이 아니라 구분 행**으로 나옵니다
(`companyGroupRowHtml` · `.group-row`). 계열사 하나에 목표가 수십 건이라 열로 두면 같은 이름이 수십 번
되풀이되면서, 읽어야 할 전략·지표 열이 밀려 좁아지고 세로로 훑을 때 어디서 회사가 바뀌는지가 오히려 묻힙니다.
회사가 바뀌는 자리에만 `계열사 이름 · N건` 한 줄을 넣고, 그만큼의 폭은 전략·지표에 돌렸습니다.
사업부도 같은 원리로 **바뀌는 행에만** 이름을 쓰고, 이어지는 행은 비웁니다.

**경영진도 드릴다운이 열려 있습니다.** 그래서 사업계획 메뉴를 경영진에게도 보여줍니다 —
숫자를 눌러 목록에 도착했는데 메뉴에는 그 화면이 없으면 돌아갈 길이 없어 길을 잃기 때문입니다.
경영진에게는 '내 차례' 탭이 늘 비어 있으므로 기본 탭이 **전체**이고, 작성·수정·삭제 버튼은 나오지 않습니다.

**연도만 사이드바에 남긴 이유**: 회사·사업부는 "지금 무엇을 보는가"를 좁히는 값이라 화면 위 필터바에 두지만,
사업연도는 그보다 한 단계 위의 맥락입니다. 한번 정하면 그 안에서 한참 일하고, 바꾸면 화면 전체가 다시 로드됩니다
(`onYearChange`가 `location.reload()`). 성격이 다른 둘을 같은 줄에 두면 연도를 자주 바꾸는 값으로 오해하기 쉽습니다.

### 목록의 SMART 본문 — 눌러서 펼친다
표에서 `S · 무엇을 / M · 어떻게 측정` 열은 **없앴습니다**. 열이 넓어 표가 복잡해 보이는 데 비해,
M은 바로 옆 `핵심지표 · 목표값` 열과 내용이 겹쳤습니다.

대신 전략(목표) 이름 앞에 **펼침 단추(›)**를 두고, 누르면 그 아래로 한 행이 열려 SMART 다섯 칸과
후속조치·비고를 2단으로 보여줍니다 (`strategyCellHtml` + `smartRowHtml` + `toggleSmart`).

**마우스오버 방식은 쓰지 않습니다.** 한 번 그렇게 만들었다가 되돌린 이유가 네 가지입니다.

1. 표가 가로 스크롤 영역(`overflow-x-auto`) 안에 있어 떠오른 카드가 **표 경계에서 잘립니다.**
2. 마우스를 떼면 사라지므로 **읽는 동안 커서를 고정**해야 합니다.
3. 글자를 **선택해 복사할 수 없습니다.**
4. 그런 기능이 있다는 것 자체를 **알아챌 방법이 없습니다.**

펼침 단추는 네 가지를 모두 해결하고, 터치 화면에서도 동작합니다.
행 전체를 누르면 목표 상세로 가므로, 펼침 단추는 `event.stopPropagation()`으로 전파를 막습니다.

#### SMART 표시는 세로 한 줄씩 (`.smart-list`)
**2열로 두지 않습니다.** 항목마다 길이가 제각각이라 한쪽에 빈 공간이 크게 남고, 눈이 좌우로 지그재그 움직입니다.

대신 **라벨을 왼쪽 고정 폭(112px)으로 빼고 내용을 오른쪽에** 둡니다. S→M→A→R→T가 위에서 아래로 곧장 읽히고,
라벨이 한 줄로 정렬돼 원하는 항목을 눈으로 바로 찾습니다. 항목 사이는 얇은 가로선으로 나눕니다.
좁은 화면(640px 이하)에서는 라벨이 내용 위로 올라갑니다.

함께 적용한 것:

- **내용은 늘 불릿 목록으로** — `common.js`의 **`textBlockHtml`**이 줄 수와 상관없이 `<ul>`로 감쌉니다.
  한 줄이어도 불릿을 붙이는 이유는, 항목마다 있고 없고가 갈리면 세로로 훑을 때 시선이 걸리기 때문입니다.
  여러 줄이면 줄마다 한 항목이 되고, 앞에 직접 찍은 `-`, `·`, `*`, `•` 기호는 불릿과 겹치므로 떼어냅니다.
- **라벨은 `[S] Specific 무엇을 할지`** — `smartLabelHtml` 한 곳에서 만듭니다.
  영어 용어 칸에 고정 폭(72px)을 줘 **한국어 질문이 모두 같은 자리에서 시작**합니다.
  단어 길이가 제각각이라(Specific 41px ~ Time-bound 62px) 고정 폭이 없으면 뒤따르는 한국어가 들쭉날쭉해집니다.
- **본문 13px · 줄간격 1.7**, 라벨 11.5px 회색 — 비중 차이를 벌려 라벨이 먼저 읽히게 합니다.
- **목록·검토·실적 입력 화면이 같은 `.smart-list`를 씁니다.** 같은 내용이 화면마다 다른 모양이면
  읽는 사람이 매번 다시 적응해야 합니다.

**펼침 단추는 모든 행에 똑같이 있습니다.** 두 가지 경우에 단추가 빠져 "저 행만 안 열린다"는 오해를 샀습니다.

- 바로 위와 전략 이름이 같아 **〃로 줄인 행** — 이름만 줄였을 뿐 다른 목표이고 SMART 내용도 따로 있습니다.
  펼침 패널 맨 위에 전략 이름과 관리번호를 한 줄 넣어, 〃 행에서도 어느 목표인지 알 수 있게 했습니다.
- **SMART가 비어 있는 목표** — 열리면 "SMART 내용이 아직 비어 있습니다"와 작성 링크가 나옵니다.
  아무 반응이 없는 것보다, 무엇이 비었는지 알려주는 편이 낫습니다.

### 알림은 토스트로 (alert 금지)
저장처럼 자주 일어나는 일에 브라우저 `alert()`를 쓰면 화면이 멈추고, 반복되면 사람들이 내용을 읽지 않고
엔터만 치게 됩니다. 전 화면의 `alert()`를 `toastOk()` / `toastError()`로 바꿨습니다(`common.js`).
**되돌릴 수 없는 일(삭제 등)만 `confirm()`을 유지합니다.** 새 화면을 만들 때도 같은 규칙을 지키세요.

### 실적 입력 단축키와 엑셀 붙여넣기
담당자는 이미 엑셀로 월별 실적을 관리합니다. 12칸을 하나씩 옮겨 적게 만들면 시스템을 안 쓰게 됩니다.

- **Enter / ↓** — 같은 열의 다음 칸으로 이동, **↑** — 이전 칸
- **붙여넣기** — 엑셀에서 세로(줄바꿈) 또는 가로(탭)로 복사한 여러 값을 한 칸에 붙여넣으면
  거기서부터 아래로 차례대로 채워집니다. `1,234` 같은 천 단위 쉼표도 받습니다.
- 채워진 칸은 `change` 이벤트를 일으키므로 **그대로 저장**됩니다. 몇 칸이 채워졌는지 토스트로 알립니다.
- 구현: `bindGridKeys(container)` — '이번 기간 입력'과 '한 해 전체 보기' 양쪽에 붙어 있습니다.

### 변경 이력 (goal_change_log)
변경요청을 거친 수정만 기록이 남던 문제를 고쳤습니다. 이제 **작성 중·검토 중에 바꾼 것도 전부 남습니다.**

- **DB 트리거가 적습니다.** 화면 코드를 고치거나 우회해도 기록을 피할 수 없습니다.
  `goals`(상태·전략명), `goal_metrics`(목표값·시작값·단위·주기·집계·지표명, 추가/삭제),
  `goal_period_targets`(기간별 목표값)에 트리거가 걸려 있습니다.
- `changed_by`는 `auth.uid()`로 자동 기록됩니다.
- **읽기 전용입니다.** SELECT 정책만 있어 사용자가 직접 넣거나 지울 수 없습니다(검증 완료).
  목표를 볼 수 있는 사람이면 그 목표의 이력도 볼 수 있습니다(`can_view_goal`).
- 화면: `goal-detail.html` 맨 아래 **변경 이력** (접힌 상태, 최근 200건).

### 목표 상세 화면 — "왜 열었는가" 순서로
이 화면을 여는 이유의 대부분은 **지금 잘 되고 있는지**와 **내가 뭘 해야 하는지**입니다.
작성 당시에 적어둔 SMART 서술은 그다음입니다. 예전에는 SMART 여섯 칸이 맨 위를 차지해
숫자를 보려면 늘 스크롤해야 했습니다. 지금 순서는 이렇습니다.

1. **길잡이** `사업계획 › 계열사 › 사업부 › 1번` — 각 단계가 그 범위로 필터된 목록으로 이어집니다(`goalsLink`).
2. **제목 · 상태 배지 · 행동 버튼** — 버튼은 지금 단계에서 할 일 하나만 주 버튼(`.btn-primary`)이고
   나머지는 보조(`.btn-ghost`)입니다. 전부 같은 무게로 늘어놓으면 뭘 눌러야 할지가 사라집니다.
   주 버튼은 `myTurnKind`로 정합니다 — 검토 차례면 **검토하기**, 작성·보완 차례면 **이어서 작성 /
   보완해서 다시 내기**, 내 차례가 아니면 **진행실적 입력**.
3. **지금 할 일 한 문장** (`.next-step`) — 내 차례면 붉은 톤으로, 아니면 "누구를 기다리는 중"인지.
   상태 배지만으로는 그래서 누가 뭘 해야 하는지가 읽히지 않습니다.
4. **한눈 요약 4칸** (`.detail-summary`) — 달성률 / 핵심지표 수 / 실적 입력 n·m기간 / 마감 지난 미입력.
   달성률은 **지표별 달성률의 단순 평균**입니다. 지표마다 단위가 달라 합산할 수 없고,
   가중치를 임의로 매기면 그 근거를 설명할 수 없기 때문입니다. 화면에도 "지표 N개 평균"이라고 적습니다.
5. **핵심지표 카드** — 전년 비교, 차트, 기간별 입력 내역.
6. **SMART** (접힘) — 목록 화면의 펼침 패널과 **같은 세로 배열**(`.smart-list`)을 씁니다.
   작성·보완·검토 차례일 때는 펼친 채로 엽니다. 그때는 서술이 주인공이기 때문입니다.
7. **검토·합의 이력 / 변경 이력** (접힘) — 단, 보완 요청 상태면 검토 이력을 펼칩니다.
   접어두면 정작 읽어야 할 사람이 의견을 못 봅니다.

| `draft` | 작성 중 |

| `baseline_value` | 시작값 (작년 실적) |
| 증가형 / 감소형 | 높을수록 좋음 / 낮을수록 좋음 |
| 합산형 / 누적형 / 평균형 | 매달 발생분 입력 / 누적된 값 입력 / 기간 평균 |

SMART 다섯 칸은 알파벳을 작은 배지로 두고 질문을 큰 글씨로 씁니다 (`SMART_FIELDS`).
각 칸 아래의 한 줄 예시도 같은 상수에서 나옵니다.

## 화면 스타일 규칙 (새 화면을 만들 때 반드시)

화면마다 색과 여백을 그때그때 정하면, 같은 시스템인데도 화면을 옮길 때마다 미묘하게 어긋나 보입니다.
어긋남은 한 군데씩 보면 티가 안 나지만 모이면 "덜 만든 것 같다"는 인상을 줍니다. 그래서 네 가지를 규칙으로 고정했습니다.

### 1. 색은 토큰으로만
`design.css` 맨 위 `:root`에 의미 단위로 모아 뒀습니다. **HTML·CSS·JS 어디에도 색상값(`#3a4356`)을 직접 쓰지 않습니다.**

| 쓰임 | 토큰 |
| --- | --- |
| 주색·강조 | `--accent` `--accent-hover` `--accent-soft` `--text-on-accent` |
| 좋음 / 주의 / 위험 | `--green` `--amber` `--red` (각 `-soft` 배경, `-ink` 글자, `-line` 테두리) |
| 정보 / 중립 / 확정 | `--blue` `--neutral-soft` `--indigo` `--locked-soft` |
| 강조 표시 | `--highlight-bg` `--highlight-line` `--highlight-ink` |

JS에서 색을 고를 때도 값이 아니라 **클래스 이름을 돌려줍니다.**

- 상태 배지 — `STATUS_BADGE_CLASS` → `.badge-draft` `.badge-submitted` `.badge-company` `.badge-revision` `.badge-approved` `.badge-locked`
- 달성률 글자 — `rateColorClass(rate)` → `.rate-good`(90↑) `.rate-warn`(60↑) `.rate-risk` `.rate-none`
- 달성률 점 — `rateDotClass(rate)` → `.dot-*` (같은 경계)
- 큰 숫자 — `.ink-good` `.ink-warn` `.ink-risk`
- 켜짐/꺼짐·집계 방식 — `.badge-on` `.badge-off` `.badge-todo` `.badge-sum` `.badge-latest` `.badge-average`

경계값(90% / 60%)이 바뀌면 `common.js` 한 곳만 고치면 전 화면에 반영됩니다.

**차트도 예외가 아닙니다.** Chart.js는 캔버스에 직접 그려서 CSS 변수를 읽지 못하므로 실제 색상 문자열이
필요합니다. 그렇다고 차트 코드에 색을 직접 적으면 화면과 차트의 색이 조용히 어긋납니다.
`common.js`의 `cssVar("--green")` / `chartColors()`로 **토큰 값을 런타임에 꺼내 씁니다.**
색 이름만 담아두는 표(`STATUS_CHART_TOKEN`)도 값이 아니라 토큰 이름을 담습니다.

### 2. 여백·모서리는 4px 그리드
`padding` `margin` `gap`은 모두 4의 배수만 씁니다(테두리 `1px`만 예외). 토큰은 `--sp-1`(4px) ~ `--sp-8`(32px).
모서리는 `--r-sm`(8) `--r-md`(12) `--r-lg`(16) `--r-pill`(999) 중에서만 고릅니다.
13px·18px처럼 눈대중으로 정한 값이 섞이면 카드가 미세하게 안 맞아 보입니다.

### 3. 제목은 `.page-title`, 버튼은 `.btn`
화면 제목에 Tailwind 조합(`text-lg font-bold text-slate-800`)을 직접 쓰지 않고 `.page-title`을 씁니다.
버튼은 `.btn .btn-primary` / `.btn-ghost` / `.btn-danger`를 쓰고, 크기만 Tailwind `!` 유틸로 조정합니다.

### 4. 배포 전 점검기 두 개를 돌립니다
"잘 만들었는지"는 사람마다 다르게 읽히므로, 기계가 매번 같은 기준으로 볼 수 있는 조건만 자동 검사합니다.
저장소 루트에서:

```
node check-ui.js      # 화면 — 색 토큰(CSS·HTML·차트 전부), :root에 없는 토큰 오타,
                      #        4px 그리드, 공통 제목·버튼, alert 금지,
                      #        화면 간 링크, 인라인 스크립트 문법, getElementById id 존재
node check-logic.js   # 계산 — 달성률(유형·집계별), 기간·마감일, 내 차례 판정,
                      #        제출 준비 조건, 지표명·불릿 표시, 조직 표시 기간
```

둘 다 실패가 있으면 종료 코드 1로 끝납니다. 현재 기준 **check-ui 실패 0건 / check-logic 통과 105건**입니다.
`check-logic.js`는 브라우저 없이 `common.js`를 가짜 `window` 위에서 실행하므로 Supabase 접속이 필요 없습니다.
새 계산 규칙을 넣으면 여기에 기대값을 한 줄 추가해 두세요 — 다음 사람이 규칙을 되돌리는 일을 막아 줍니다.

> 참고: 두 점검기는 `wrangler.jsonc`의 `assets.directory: "."` 때문에 배포 시 함께 올라갑니다.
> 비밀값은 없어 위험하지 않지만, 공개하지 않으려면 `dev/` 폴더로 옮기고 `assets.directory`를 `web`으로 좁히면 됩니다.

## 기간별 목표 참고값 (referencePeriodTarget)
기간별 목표값을 따로 설정하지 않은 지표에서 "이번 달 목표"를 화면마다 다르게 계산하면
같은 지표가 화면마다 다른 목표로 보입니다. 그래서 `common.js`의 `referencePeriodTarget()` 한 곳에서만 계산하고
진행실적 입력·목표 상세 차트·변경요청·목표 작성(균등분배)이 모두 이 함수를 씁니다.

- 합산형: `연간 목표 ÷ 기간수`
- 누적형: `기준값 + (목표값 − 기준값) × (n/기간수)` — **기준값에서 출발**합니다.
  (예: 정기배송 회원수 기준값 10,000 → 목표 11,500이면 1월 10,125 … 12월 11,500)
- 평균형: 매 기간 연간 목표 수준 유지
- 연간 목표값이 없으면 `null`(표시는 "미설정")

설정값이 아니라 계산된 참고값이므로 화면에는 `(참고)` 또는 `미설정 · 연간기준 N`으로 표기합니다.

## 목표 변경요청 화면 (change-requests.html) — 관리자 결정용

지주사 담당자가 **이 화면만 보고 합의할지 반려할지 정할 수 있어야** 합니다. 그래서 세 가지를 한 카드에 담습니다.

1. **변경 사유** — 맨 위에 눈에 띄게. 비어 있으면 "사유가 적혀 있지 않습니다"라고 밝힙니다.
   사유는 필수가 아니지만, 비운 채 제출하면 한 번 더 확인을 받습니다.
2. **무엇이 바뀌나** — `변경 전 → 변경 후`를 나란히 두고 **변화폭**을 함께 적습니다 (`1,000 → 1,300`, `+300 (+30%)`).
   목표 본문·지표 속성·기간별 목표값을 모두 같은 형식으로 보여줍니다.
3. **영향** — 이미 입력된 실적이 있으면 `달성률 102% → 79% (실적 7건 재계산)`처럼
   변경 후 달성률을 미리 계산해 보여줍니다(`impactHtml`).

목록은 **결정 대기 건이 위**, 처리된 건은 접어둡니다. 반려할 때는 이유를 받아 `review_comment`에 남기고,
처리자·처리일시·처리 의견이 카드에 그대로 표시됩니다.

## 변경요청 작성 (goal-detail.html → change-requests.html?goal=…)
"무엇을 얼마로 바꿀지" 판단하려면 현재 상태가 같이 보여야 합니다.
- 지표마다 **요약 바**에 유형·집계 방식·기간유형, 기준값 → 연간 목표, 현재 실적과 달성률, 입력된 기간 수를 표시합니다.
- 기간별 목표값 칸에는 설정값이 있으면 값을, 없으면 **`미설정 · 연간기준 N`** 으로 연간 목표를 집계 방식에 맞게 나눈 참고값을 보여줍니다
  (합산형은 ÷기간수, 누적형은 누진, 평균형은 동일값). 단위도 함께 붙습니다.
- 각 기간에 **입력된 실적**이 있으면 파란색으로 함께 표시합니다. 목표 조정은 대개 실적을 보고 판단하기 때문입니다.
- 실적이 입력된 지표는 "목표값을 바꾸면 달성률이 다시 계산됩니다" 경고를 띄웁니다.
- 지표명·유형·단위는 KPI 기준정보 소속이라, 변경요청으로 바꾸면 이 목표에만 적용되어 연도별 표기가 어긋날 수 있습니다.
  해당 항목에 경고를 표시하며, 원칙적으로는 `kpi.html`에서 수정해야 합니다.

## 목표 삭제
- **임시저장(`draft`) 상태에서만** 삭제할 수 있습니다. 제출 이후에는 결재 이력이 남아야 하므로,
  먼저 [제출취소]로 임시저장으로 되돌린 뒤 삭제합니다. (`goals_delete` RLS 정책이 DB에서 강제)
- 삭제 권한 범위는 목표 작성 권한과 같습니다 — 사업부 담당자는 담당 사업부, 계열사 담당자는 자기 회사,
  지주사 담당자는 전사. 지주사 경영진(조회 전용)은 삭제할 수 없습니다.
- 목표를 지우면 핵심지표·기간별 목표값·실적·검토 이력이 DB에서 CASCADE로 함께 삭제됩니다.
  **스토리지의 증빙파일은 CASCADE 대상이 아니므로** `deleteGoalCascade()`가 먼저 파일을 지우고 목표를 삭제합니다.
- 삭제 확인창에 함께 사라지는 지표·실적·첨부파일 건수를 표시합니다(`goalDeleteImpact`).
- 삭제하면 그 관리번호는 비워둡니다(뒤 번호를 당기지 않음).

## 실적 입력 주기 (period_type)
`monthly` 월별 / `quarterly` 분기별 / `half` 반기별 / `annual` 연 1회

기간 문자열은 `2026-01`, `2026-Q1`, `2026-H1`, `2026-Y` 형식입니다.
관련 로직은 모두 `common.js` 한 곳에 있습니다.
- `periodsForYear(year, type)` — 입력 칸 개수(12 / 4 / 2 / 1)를 정합니다.
- `periodDisplayLabel(period)` — `3월` / `2분기` / `상반기` / `연간` 표기.
- `periodDeadline(period, type)` — **그 기간이 끝나는 달의 다음 달 말일**까지가 입력 마감입니다.
  상반기 → 7/31, 하반기·연간 → 이듬해 1/31. 미입력 알림·대시보드 위험 판정이 이 값을 씁니다.
- `elapsedRatio(year, type, now)` — 진도율 계산. 연 1회는 항상 1(진도율 개념이 없음).
- Edge Function(`notify-reminders-index.ts`)에도 같은 규칙의 복사본이 있으니 함께 수정해야 합니다.

## KPI 집계 방식 (합산 / 누적 / 평균)
같은 지표라도 "당월 발생분"을 넣는 사람과 "누적값"을 넣는 사람이 섞이면 달성률이 틀어집니다.
실제로 도입 전에는 `연단체 수`(누적 입력)는 맞게 나오고 `매출`(당월 입력)은 60%로 잘못 나오고 있었습니다.
그래서 집계 방식을 **지표의 속성**(`kpi_definitions.accumulation` → `goal_metrics.accumulation`)으로 고정합니다.

| 방식 | 입력 방법 | 연간 실적 | 예시 |
| --- | --- | --- | --- |
| `sum` 합산형 | 그 기간에 발생한 실적 | 합계 | 매출액, 수주건수 |
| `latest` 누적형 | 연초부터의 누적값·시점 잔량 | 마지막 값 | 연단체 수, 재적 회원수, 누적 감축량 |
| `average` 평균형 | 그 기간의 값 | 기간 평균 | 원가율, 가동률, 만족도 점수 |

방식에 따라 화면 동작이 함께 달라집니다.
- **기간별 목표값 검증**: 합산형은 합계, 누적형은 마지막 기간 값, 평균형은 평균이 연간 목표와 일치해야 합니다.
- **연간값 자동 분배**: 합산형은 균등 배분(÷12), 누적형은 균등 진행(100→200→300…), 평균형은 전 기간 동일값.
- **차트 누적 모드**: 누적형은 입력값이 이미 누적이라 더하지 않고 그대로 그립니다(합산하면 중복 집계).
- **실적 입력 화면**: 지표마다 "당월 실적을 입력하세요" / "연초부터 누적된 값을 입력하세요" 안내가 표시됩니다.
- 계산은 `common.js`의 `annualActual` / `achievementRate` 한 곳에 모여 있고, 목표 상세·대시보드·변경요청이 모두 이 함수를 씁니다.

## 달성률 계산 규칙 (중요)
**달성률은 "실적이 입력된 기간의 목표"와만 비교합니다.**

예전에는 연간 실적 ÷ 연간 목표로 계산했는데, 7월까지 입력한 실적을 12개월 전체 목표와 비교하게 되어
합산형 지표에서 크게 왜곡됐습니다. (월 목표·실적이 매달 똑같이 1,1,2,2,3,3,3인데 연간 목표가 5라 **300%** 로 표시)

`achievementRate(metric, entriesAsc, periodTargetMap, year)`는
1. 실적이 입력된 기간만 골라
2. 각 기간의 목표(설정값 우선, 없으면 `referencePeriodTarget` 참고값)를 짝지어
3. 양쪽을 같은 집계 방식으로 묶어 비교합니다.

그래서 **집계 방식(합산/누적/평균)이 무엇이든 "목표만큼 했으면 100%"** 가 나옵니다.
기간 유형이 바뀌어 짝이 맞지 않는 옛 실적(`2026-Q1` 형식 등)은 계산에서 제외합니다.

보조 표시:
- `progressSubText` — `7/12기간 입력 · 연간 목표의 300%`처럼 연간 목표 대비 진척을 별도로 보여줍니다.
- `targetConsistencyWarning` — 기간별 목표를 집계 방식대로 묶은 값이 연간 목표값과 다르면 경고합니다.
  (합산형인데 월 목표를 누적값으로 넣은 경우 등)

기존 59건은 이름 패턴으로 자동 배정했습니다(누적/연단체/회원수 → 누적형, 율·률·점수 → 평균형, 나머지 → 합산형).
`kpi.html`의 **집계** 열에서 계열사 담당자가 검수·수정할 수 있습니다.

## KPI 달성 차트 (goal-detail.html)
목표·실적·달성률을 이중축 한 장에 겹치지 않습니다. 달성률은 목표·실적에서 계산된 파생값이라 같은 정보를 두 번 그리게 되고,
축이 두 개면 선과 막대의 교차점이 아무 의미가 없는데도 신호처럼 읽히기 때문입니다.
대신 **축을 하나만 쓰는 두 관점을 토글**로 제공합니다.

- **누적(기본)**: 누적 목표선 vs 누적 실적선. "연말에 목표를 채울 수 있나"를 보는 관점.
  기간별 목표 합계가 연간 목표값과 다르면 연간 목표 기준선을 점선으로 따로 표시합니다.
- **기간별**: 목표·실적 클러스터드 컬럼. 달성 기간은 초록, 미달 기간은 빨강으로 칠합니다.
- 달성률은 축으로 만들지 않고 카드 우상단 배지와 툴팁 숫자로 보여줍니다.
- **실적이 입력되지 않은 기간은 그리지 않습니다**(0으로 찍으면 미달성으로 오해되기 때문).
- 기간별 목표값이 없고 연간 목표만 있으면 균등 배분한 **점선 참고선**으로 그리고 "연간 목표 균등 배분(참고)"이라고 명시합니다.
- 감소형은 낮을수록 좋은 지표라 색 판정을 반대로 적용합니다.
- 마일스톤은 값 개념이 없어 차트 대신 **기간별 완료 타임라인**, 진척도(%)형은 0~100 단일 라인으로 표시합니다.
- 목표값이 없으면 "목표값을 입력하면 목표선이 표시됩니다" 안내를 띄웁니다.

## KPI 기준정보 (연도별 비교의 기준)
지표명을 매년 자유 텍스트로 다시 적으면 표기가 조금만 달라져도 전년 비교가 끊깁니다.
그래서 지표는 **이름이 아니라 id로** 잇습니다.

- `kpi_definitions` (계열사별 KPI 마스터): 지표명, 유형, 단위, 기본 기간유형, 정의 메모, 사용여부.
  `(company_id, name_norm)` 유니크라 공백·대소문자만 다른 중복 등록은 DB에서 차단됩니다.
- `goal_metrics.kpi_definition_id` 가 매년 작성되는 지표를 이 마스터에 연결합니다.
  **마스터의 이름을 바꿔도 연결은 id로 유지**되므로 표기를 정비해도 과거 데이터와의 비교가 끊기지 않습니다.
- 목표 작성 화면의 지표 선택은 **두 가지 경로(하이브리드)** 입니다. 브라우저 기본 `datalist`는 부가 정보를 못 보여주고
  항목이 많아지면 스크롤 외에 방법이 없어 직접 구현했습니다.
  - **입력칸 자동완성**: 타이핑하면 지표명과 함께 유형·단위·사용 연도가 표시됩니다. ↑↓ + Enter로 선택,
    **초성 검색**(`ㅁㅊ` → 매출액) 지원, 맨 아래 "'OOO' 새 지표로 등록" 항목.
  - **돋보기 버튼 → 지표 찾기 팝업**: 이름을 모를 때 둘러보는 경로. `우리 사업부 / 회사 전체` 탭,
    검색, 사용 목표 건수 표시, 검색 결과가 없으면 팝업 안에서 바로 신규 등록.
  - 정렬은 **최근 사용 연도 → 사용 횟수 → 이름** 순입니다(작년에 쓴 지표가 올해도 쓰일 확률이 높으므로).
- **유형·단위는 지표의 속성이지 올해 목표의 속성이 아닙니다.** 기준정보에 연결된 지표는 이 둘을 입력칸이 아니라
  `증가형 · 억원` 배지로 표시만 하고, 매년 다시 고르지 않습니다. 기간유형(월별/분기별)만 연도별로 바뀔 수 있어 편집 가능합니다.
  - [속성 수정]을 누르면 편집으로 전환되고, 저장 시 **기준정보에도 함께 반영**됩니다(계열사·지주사 담당자).
  - 기준정보에 단위가 비어 있으면 누구나 [단위 입력]으로 채울 수 있고, 그 값이 기준정보에 저장되어
    다음부터 자동으로 들어갑니다(`fill_kpi_definition_defaults` RPC — 비어 있는 값만 채우고 기존 값은 덮어쓰지 않음).
  - `kpi.html`은 단위가 비어 있는 지표를 주황색으로 표시하고 건수를 안내해, 미리 채워두도록 유도합니다.
- 목록에 없는 이름을 적으면 저장할 때 기준정보로 자동 등록됩니다(작성자 누구나 등록 가능).
  비슷한 이름이 있으면 "혹시 이 지표인가요?" 경고가 뜹니다.
- `goals.html`의 **[작년 목표 불러오기]** 로 전년도 전략·지표를 복사해 올해 초안을 만듭니다(기준값·목표값은 비움).
  이름을 다시 타이핑할 일이 없어지므로 기준정보가 자연스럽게 유지됩니다.
- `kpi.html` (KPI 기준정보 관리, 계열사·지주사 담당자): 이름·단위·유형 수정, **병합**(중복 등록된 지표를 합치면 과거 실적까지 하나로 이어짐),
  숨김(새 작성 목록에서만 제외). 사용 중인 지표는 FK로 삭제가 막혀 실적이 유실되지 않습니다.
- `goal-detail.html`의 각 지표 카드에 **전년도 목표·실적·달성률**이 표시됩니다(같은 사업부 우선).
- `goals.indicator_name` 은 `goal_metrics.metric_name` 과 중복되는 옛 필드입니다. 새로 만드는 목표에는 값이 들어가지 않습니다.

### 지표명 표시 규칙 (중요)
목록·대시보드에서 목표 한 줄은 항상 **전략(목표) + KPI 지표명** 구조입니다. Specific 등 SMART 본문은 이 자리에 나오지 않습니다.
지표명은 `common.js` 의 **`goalMetricNames(goal, metrics)`** 한 곳에서만 만들며, 순서는 다음과 같습니다.

1. `goal_metrics` 의 지표명 (기준정보 `kpi_definitions.name` 이 있으면 그 이름이 우선 — 기준정보에서 이름을 고치면 전 화면에 즉시 반영)
2. 지표가 여러 개면 ` / ` 로 이어 붙임
3. `goal_metrics` 가 없는 과거 데이터만 `goals.indicator_name` 으로 보완
4. 둘 다 없으면 대시보드는 `KPI 지표 미등록` 으로 표시

새 화면을 만들 때 `goals.indicator_name` 을 직접 읽지 말고 이 함수를 쓰세요. 직접 읽으면 `goal_metrics` 로만 지표를 등록한
최근 목표에서 지표명이 비어 보이고, Specific 본문으로 대체되는 문제가 생깁니다.

## 목표 작성 화면 (goal-form.html) — 3단계

한 화면에서 20칸 넘게 묻던 폼을 세 단계로 나눴습니다.

| 단계 | SMART | 묻는 것 |
| --- | --- | --- |
| 1 | **S** | 사업부 · 전략(목표) 이름 · 무엇을 할지 |
| 2 | **M** | KPI 지표 · **올해 목표값** · 기간별 배분 · 어떻게 잴지 |
| 3 | **A · R · T** | 가능한 근거 · 왜 중요한지 · 언제까지 (+ 후속조치·비고는 선택) |

**SMART 다섯 칸은 모두 선택입니다** (운영 정책). 비어 있어도 제출을 막지 않습니다.
단계를 나눈 것은 한 화면의 부담을 줄이기 위한 것이고, SMART 칸의 배치는 그 틀을 유지합니다.
M을 2단계에 둔 것은 '어떻게 잴지'가 곧 측정 방법이라 KPI 옆이 제자리이기 때문입니다.

**제출을 막는 것은 '없으면 관리 자체가 불가능한 것'뿐입니다.**

| 항목 | 필수 여부 | 이유 |
| --- | --- | --- |
| 전략(목표) 이름 | **필수** | 목록·보고서에 그대로 나오는 이름 |
| KPI 지표 | **필수** | 달성 여부를 잴 수단 |
| 목표값 (연간 또는 기간별) | **필수** | 없으면 달성률 계산 불가 |
| 단위 | **필수** | 없으면 숫자만 남아 억원인지 건인지 알 수 없음 |
| S · M · A · R · T | 선택 | 적어두면 검토가 빨라지지만 막지 않음 |
| 후속조치 · 비고 | 선택 | |

비어 있다는 사실은 숨기지 않되, 흐름은 끊지 않습니다.

- **제출 버튼 옆에 빈 칸을 늘 적어둡니다**(`updateSubmitHint`) — `A · 가능한 근거, T · 언제까지 비어 있음
  (선택 항목이라 이대로 제출할 수 있습니다)`. 타이핑하는 대로 갱신됩니다.
  **확인창은 띄우지 않습니다.** 매번 누르게 되면 결국 읽지 않기 때문입니다.
- **검토 화면**은 SMART 빈 칸을 경고로 표시합니다. 검토자가 보고 수정요청으로 되돌려 보낼 수 있습니다.
- **제출은 2단계부터** 가능합니다. 지표까지 정해지면 낼 수 있습니다.
- **'임시저장' 버튼은 없습니다.** 타이핑이 멈춘 뒤 자동 저장되고(`markDirty` → `autosave`),
  단계를 넘길 때 그 단계만 검증하고 저장합니다(`leaveStep`). 지표는 2단계를 떠날 때 저장됩니다.
- 목록의 '제출 가능 / ○○ 필요' 표시도 같은 규칙(`submitReadiness`)을 씁니다.

> SMART를 필수로 바꾸려면 `submitReadiness`에 `SMART_FIELDS` 검사를 되살리고,
> `goal-form.html`의 라벨에서 `(선택)`을 떼면 됩니다. 두 곳만 고치면 정책이 바뀝니다.
- **목표값이 2단계의 주인공**입니다. 올해 목표값을 넣으면 기간별 목표가 집계 방식대로 **자동 분배**됩니다
  (`autoFillPeriods`). 사용자가 한 칸이라도 직접 고치면 `periodAuto=0`이 되어 더 이상 덮어쓰지 않습니다.
- **단위는 필수**입니다. 비워둔 채 저장되면 나중에 숫자만 남아 억원인지 건인지 알 수 없게 됩니다.
  이름에 매출·금액·이익·원가 등이 들어가면 그룹 표준 단위(`MONEY_UNIT_DEFAULT` = 백만원)를 미리 넣어줍니다.
- 작성 시작 화면에 **작년 목표 불러오기** 배너가 뜹니다. 작년 목표값은 올해 **시작값**으로 옮겨져,
  올해 목표값만 채우면 되도록 복사됩니다.

## 핵심지표(KPI) 입력 규칙
- 목표당 지표는 **최소 1개**, 지표명은 필수이며 같은 목표 안에서 중복될 수 없습니다(공백·대소문자 무시 비교).
- 정량형(높을수록/낮을수록 좋음)은 **연간 목표값이나 기간별 목표값 중 하나는 반드시** 있어야 합니다.
  - 목표값 0은 달성률 계산이 불가능하므로 막습니다.
  - 단위가 비어 있으면 저장되지 않습니다.
  - 낮을수록 좋은 지표는 시작값이 필수입니다(달성률 = (시작값 − 실적) ÷ (시작값 − 목표값)).
- 정성형(마일스톤·진척도)은 기준값·목표값·단위를 저장하지 않습니다(화면에서 감춘 값이 남아 저장되던 문제 방지).
- **저장 순서**: 모든 검증을 통과한 뒤에야 DB에 씁니다. 예전에는 지표를 먼저 삭제하고 검증해서, 검증에 걸리면 기존 지표가 사라졌습니다.
- **지표 id 유지**: 수정 저장 시 기존 지표는 `update`로 갱신하고, 화면에서 제거된 지표만 삭제합니다.
  지표를 삭제하면 `progress_entries`가 CASCADE로 함께 지워지므로, 실적이 있는 지표를 지울 때는 화면에서 경고합니다.
- 신규 작성 중 오류가 나도 목표가 중복 생성되지 않도록, 목표 생성 직후 수정 모드로 전환합니다(URL에 `?id=` 반영).

## 목표 관리번호(seq_no) 채번 규칙
- 번호는 **연도 + 계열사 + 사업부** 그룹 안에서 1번부터 매겨집니다. → "2026년 강원심층수 영업 1번 목표"
- 사업부를 지정하지 않은 전사 공통 목표는 `business_unit_id IS NULL` 끼리 하나의 그룹으로 묶여 따로 채번됩니다.
- 신규 등록 시 `trg_assign_goal_seq_no` 트리거가 자동으로 다음 번호를 부여합니다(화면에서 입력하지 않음).
- 목표의 사업부(또는 연도·계열사)를 바꾸면 **옮겨간 그룹 기준으로 번호가 다시 부여**됩니다. 내용만 수정하면 번호는 그대로입니다.
- `goals_seq_no_per_group_key` 유니크 인덱스(`NULLS NOT DISTINCT`)가 같은 그룹 내 번호 중복을 DB에서 차단합니다.
- 목표를 삭제하면 그 번호는 비어 있는 채로 남습니다(기존 번호를 밀어서 바꾸지 않음 — 이미 공유된 번호가 달라지는 것을 막기 위함).
- 목록 화면은 사업부로 묶은 뒤 번호 순으로 정렬합니다(`common.js`의 `sortGoalsByBusinessUnit`).

## 로그인 세션 정책
- 로그인 토큰은 **sessionStorage**에 저장됩니다(`js/common.js`의 `AUTH_STORAGE`).
  브라우저나 탭을 닫으면 토큰이 사라지므로, 다시 접속하면 로그인 화면부터 시작합니다.
- sessionStorage는 탭 단위로 유지되므로 같은 탭 안에서 페이지를 이동하는 것(이 앱은 전체 새로고침 방식)에는 영향이 없습니다.
- 방식 전환 이전에 localStorage에 남아 있던 `sb-*-auth-token` 키는 페이지를 열 때 자동으로 정리됩니다.
  그래서 전환 직후 한 번은 기존 사용자 전원이 다시 로그인해야 합니다.
- 한계: 크롬의 "중단한 부분부터 계속하기"(세션 복원)가 켜져 있으면 탭과 함께 sessionStorage까지 복원될 수 있어 100% 보장은 아닙니다.
  또한 링크를 새 탭으로 열면 그 탭에서는 다시 로그인해야 합니다.
- 더 엄격하게 막으려면 ① 앱 레벨 유휴 타임아웃(마지막 활동 후 N분 경과 시 자동 로그아웃) 추가,
  ② Supabase Pro 플랜의 Time-box / Inactivity timeout 사용을 검토할 수 있습니다.

## 비밀번호 관리
- **본인 변경**: 로그인 후 좌측 사이드바 하단 [비밀번호 변경] → `password.html`.
  현재 비밀번호로 본인 확인 후 새 비밀번호를 설정합니다. (8자 이상 + 영문·숫자·특수문자 중 2종류 이상)
- **최초 로그인 강제 변경**: 계정 생성 시 `profiles.must_change_password = true`가 기본값이라,
  관리자가 발급한 초기 비밀번호로 처음 로그인하면 `password.html`로 자동 이동하며
  비밀번호를 바꾸기 전에는 다른 화면으로 이동할 수 없습니다(사이드바·취소 버튼도 숨김).
- 이메일 링크로 직접 비밀번호를 설정한 경우(`reset-password.html`)에는 중복으로 요구하지 않고 자동 해제됩니다.
- 관리자가 비밀번호를 재발급해준 경우, `admin.html`의 [변경 요구] 버튼으로 강제 변경 절차를 다시 걸 수 있습니다.
- 기존에 이미 사용 중이던 계정은 이 기능 도입 시점에 변경 요구 대상에서 제외되었습니다.

## 권한 구조 (지주사 - 계열사 - 사업부 3단계)

| 역할 | 조회 범위 | 주요 권한 |
| --- | --- | --- |
| 사업부 담당자 (`bu_staff`) | 배정된 사업부만 | 목표 작성 → 계열사 검토 제출, 실적 입력 |
| 계열사 담당자 (`company_staff`) | 자기 회사 전체 사업부 | 사업부 제출 목표 검토(합의/수정요청), 전사 목표 직접 작성, 사업부 등록·병합 |
| 지주사 담당자 (`holdco_staff`) | 전 계열사 | 최종 합의/반려, 계정·권한 관리(유일), 계열사·사업부 관리 |
| 지주사 경영진 (`holdco_exec`) | 전 계열사 | 조회 전용 |

- 계정·권한 배정(역할 지정, 사업부 배정)은 **지주사 담당자만** 가능합니다. (`profile_business_units` 테이블 RLS로 강제)
- 사업부 담당자는 겸직이 가능하며, 여러 사업부를 배정받을 수 있습니다.

### 목표 결재 흐름
```
사업부 담당자 작성 → [작성 중]
      ↓ 계열사 검토 제출
[계열사 검토 중] ── 수정요청 → [수정 요청됨] (사업부가 고쳐서 재제출)
      ↓ 계열사 합의
[지주사 검토 중] ── 수정요청/반려 → [수정 요청됨] / [작성 중]
      ↓ 지주사 최종 합의
[확정]
```
- 계열사 담당자가 직접 작성한 목표는 제출 시 곧바로 `지주사 검토 중` 상태가 됩니다.
- 월별/분기별 **실적 입력은 별도 결재 없이** 입력 즉시 반영됩니다.

### 검토 화면 (review.html) — 숫자를 보고 합의한다
검토 카드에는 SMART 본문이 아니라 **KPI 지표·목표값 표가 먼저** 나옵니다.
지표명 · 방향 · 집계/주기 · 시작값 · 올해 목표 · 단위 · 작년 목표/실적이 한 줄씩 보입니다.

**합의 버튼이 잠기는 조건** (`checkGoal`의 blockers):
- KPI 지표가 하나도 없을 때
- 정량 지표에 목표값(연간·기간별 모두)이 없을 때
- 정량 지표에 단위가 없을 때

막지는 않지만 경고로 알리는 것(warnings): 기간 목표 합계가 연간 목표와 다를 때(`targetConsistencyWarning`),
‘무엇을 할지’가 비어 있을 때.

수정요청을 보낼 때는 **어느 지표에 대한 의견인지** 드롭다운으로 고를 수 있고, 의견 앞에 `[지표명]`이 붙어
작성자 홈에 그대로 전달됩니다.

### 실적 입력 화면 (progress.html) — 이번 기간이 기본
- 기본 탭은 **이번 기간 입력**입니다. 확정(또는 잠김) 목표의 지표를 모아 **지금 채워야 할 칸 하나씩**만 보여줍니다.
  `마감이 지난 칸` / `이번 기간` 두 묶음으로 나누고, 각 묶음 안에서 **사업부별로 다시 묶습니다.**
- **한 해 전체 보기**는 `회사 › 사업부 › 목표` **세 칸 선택기**입니다(`.col-picker`).
  왼쪽에서 고를수록 오른쪽이 좁혀지므로, 목표가 수십 건이어도 몇 번의 클릭으로 찾습니다.
  **회사 칸은 소속 회사가 하나뿐이어도 항상 보여줍니다** — 칸이 상황에 따라 나타났다 사라지면
  화면 구조가 매번 달라져 오히려 헷갈리기 때문입니다. 검색어를 넣으면 세 칸이 모두 그 결과 기준으로 다시 계산됩니다.
- 각 칸 옆에 **지난 기간 입력값을 회색으로** 보여줍니다. 누적형 지표에 당월 실적을 넣는 실수가 여기서 드러납니다.
- **저장 버튼이 없습니다.** 칸을 벗어나면 저장됩니다(`bindNowRows`).
- 지난 기록을 보거나 한 해를 통째로 채울 때도 같은 탭을 씁니다 (12개월 격자, 일괄저장 포함).

### 현황 화면 (dashboard.html)
- 맨 위에 결론을 **한 문장**으로 먼저 말합니다(`renderLead`).
- 기본은 **확정된 목표만** 집계합니다. 작성 중인 목표가 섞이면 전사 달성률이 실제보다 낮게 보이기 때문입니다.
  `작성 중인 목표까지 포함` 토글로 전체를 볼 수 있습니다(`applyScope`).
- 달성률이 비어 있는 이유를 **'목표값 없음'과 '실적 없음'으로 구분**합니다(`rateUnknownLabel`).
  앞의 것은 계획을 고쳐야 하고, 뒤의 것은 실적을 넣어야 하는, 전혀 다른 상황입니다.

### 계열사·사업부 마스터 관리 (숨김 / 삭제)
- `companies.html`(계열사 관리, 지주사 담당자 전용), `business-units.html`(사업부 관리, 계열사·지주사 담당자)
- **표시 기간**(`active_from_year` / `active_to_year`): 연도별로 대상 조직이 달라지는 경우에 사용합니다.
  - 종료 연도를 `2025`로 지정하면 → 2026년 이후 대시보드·목표 목록·필터에서 제외되고, **2025년 이하를 조회하면 과거 실적이 그대로 보입니다.**
  - 시작 연도를 `2027`로 지정하면 → 2027년부터 노출됩니다. (신설 계열사·사업부를 미리 등록할 때)
  - 판정 규칙은 `common.js`의 `isVisibleInYear()`(조회 노출) / `isSelectableInYear()`(신규 선택 가능) 한 곳에 모여 있습니다.
- **전체 숨김**(`is_active = false`, 표시 기간 미지정): 연도와 무관하게 모든 조회 화면에서 제외됩니다.
  과거 연도 대시보드에서도 사라지므로, 지난 실적을 계속 보려면 전체 숨김 대신 표시 종료 연도를 쓰세요.
  이미 입력된 목표·실적·첨부파일은 전혀 건드리지 않으며, 과거 데이터 화면에는 그대로 표시됩니다.
  숨긴 사업부로 등록된 기존 목표를 수정할 때는 해당 사업부가 `(숨김)` 표기와 함께 선택 목록에 계속 남습니다.
- **삭제**: 연결된 데이터(목표·사업부·계정)가 하나도 없을 때만 가능합니다.
  데이터가 있는 계열사·사업부는 삭제 대신 숨김 처리하도록 막아, 과거 실적이 유실되지 않게 합니다.

### 사업부 중복 등록 방지
- `business_units`에 공백·대소문자를 무시한 정규화 이름(`name_norm`) 기준 회사별 유니크 인덱스가 걸려 있어,
  "온채널"과 "온 채널"처럼 표기만 다른 중복 등록이 DB 레벨에서 차단됩니다.
- 이미 생긴 중복은 `business-units.html`(사업부 관리)의 **병합** 기능으로 정리할 수 있습니다.
  병합 시 해당 사업부의 목표와 담당자 배정이 대상 사업부로 모두 이관됩니다. (`merge_business_unit` RPC)
